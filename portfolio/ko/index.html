01

자기소개

법을 공부하다 보니 어느새 서버까지 운영하고 있습니다. 관심이 생긴 일은 일단 직접 해 보는 성격입니다.

주오대학 법학부 법률학과 4학년으로 법학을 공부하면서, Minecraft 서버의 운영 멤버로서 인프라 관리에도 참여하고 있습니다.

처음 서버 관리에 발을 들인 계기는 우연에 가까웠습니다. 당시 참여하던 서버의 운영이 더는 이어지기 어려워진 시점에, 마침 자금에 여유가 있던 제가 얼떨결에 VPS를 빌려 관리를 넘겨받게 된 것이었습니다. 이후에는 오래된 노트북을 이용한 자택 서버 운영으로 자리를 잡았고, 처음에는 Dynmap조차 없는 최소 구성에서 출발했습니다. 원래 사이버 공격의 종류나 수법에는 예전부터 관심이 있었는데, 참여자들을 위해 기능을 하나씩 추가해 나가는 과정에서 그 관심과 서버 관리라는 역할이 잘 맞물린다는 것을 깨닫게 되었습니다. "모두를 위해 더 나은 것을 제공하고 싶다"는 마음과, "공개 범위가 넓어질 때마다 보안 구멍을 하나씩 메워 나간다"는 인프라 보안 특유의 퍼즐 같은 재미가 맞아떨어지면서, 강한 호기심과 보람을 느끼게 되었습니다. 지금은 보안을 포함한 인프라 엔지니어링 전반이 관심의 중심에 있습니다.

법에 대한 관심도 거슬러 올라가면 보안에 대한 흥미에서 비롯되었습니다. 원래는 공학부 진학도 생각하고 있었지만, Winny 사건을 알게 된 것이 계기가 되었습니다. 소프트웨어 개발자를 둘러싼 그 사건이 보안 엔지니어의 입장과도 통하는 면이 있다고 느꼈습니다. 공격을 막으려면 공격 수법 자체를 깊이 이해해야 하고, 공격과 방어는 동전의 양면입니다. 그런 기술자와 연구자를 법률적인 측면에서 뒷받침하는 인력이 필요하다는 점을 의식하게 된 것이 법학에 대한 관심의 출발점이었습니다. 여기에 더해, 실제로 서버 규칙을 조문화하는 작업에 참여하면서 의미의 오해를 막기 위한 법령 용어의 고민이나, 치밀하면서도 어딘가 인간미가 있는 조문 해석의 논의에 매력을 느껴, 법학도로서 본격적으로 법을 공부하기로 결심했습니다.

중요하게 여기는 것은 관심이 생긴 일에 대해 타협하지 않는 것입니다. 법에 관심이 생기면 법학부에서 공부하고, 서버 인프라에 관심이 생기면 실제로 서버를 세우고 가상화에도 도전한다. 그렇게 관심이 이끄는 대로 행동을 쌓아 왔습니다. 그 바탕에는 "누군가를 위해" 무언가를 하고 싶다는 마음이 강하게 자리하고 있으며, 참여자를 위해 서버를 개선하는 일도, 보안 엔지니어를 뒷받침하는 법률가라는 장래상도 이 마음에서 출발합니다.

03

기술

학업과 병행하여 서버 운영 실무 속에서 익혀 온 기술을 중심으로 적었습니다. level은 자기 평가 5단계입니다(● 개수가 많을수록 숙련도가 높음).

클라우드 / 인프라

  • Proxmox VE

    물리 서버 2대를 클러스터화하고, SDN(VXLAN)으로 가상 네트워크를 구축, LXC·VM 7대 이상을 운영

  • Linux (Debian)

    모든 컨테이너·VM의 기반 OS로서 서비스 구축·systemd 관리를 담당. 개인용 노트북에서도 Ubuntu 계열 OS를 사용

  • Tailscale

    ACL 태그로 역할을 분리하여, 관리자·모니터링·Minecraft 서버 간의 접근 경로를 설계

  • Cloudflare (Workers / Tunnel)

    Tunnel＋Discord OAuth로 운영진용 서비스를 공개하고, Workers로 OpsBot의 백엔드와 REWIS의 외부 데이터 정본을 구축

관측 가능성 / 운영

  • Prometheus / Grafana

    TPS·가동 상태·네트워크 상태 모니터링과 7종의 알림 규칙을 정비. 모니터링 대상은 필요에 따라 조금씩 시행착오를 거치며 확장 중

  • Crafty Controller

    venv 구성 설치·systemd 서비스화·자동 재시작 설정까지 포함해, 팀 전체가 다룰 수 있는 GUI 관리 환경을 정비

개발

  • JavaScript

    REWIS의 프런트엔드(바닐라 JS)와 PWA 대응을 구현

  • Python

    OpsBot의 CT102 쪽(폴링 처리·외부 API 연동)을 구현

  • TypeScript

    OpsBot의 Cloudflare Workers 쪽 백엔드를 구현

  • HTML / CSS

    REWIS의 UI 설계·스타일링을 처음부터 구축

법학

  • 헌법

    세미나에서 헌법학을 연구. 서버 규칙 기초 작업에서 운영 권한의 설계에도 응용하고 있다

04

실적·작품집

서버 운영·개인 개발 중에서 공개할 수 있는 것을 4건 실었습니다.

Minecraft 서버 인프라 구축·운영

자택 서버 2대를 Proxmox 클러스터로 묶어, Minecraft 서버와 주변 서비스를 접근 제어까지 포함해 구축·운영

역할
서버 구축·인프라 관리 담당
기간
2022.11 — 현재

처음에는 Ubuntu 기기에 서버 소프트웨어만 올려 둔 상태에서 시작했지만, 참여자·운영팀·본인(관리자)이라는 세 종류의 이용자별로 "어디까지 접근을 허용할 것인가"를 정리할 필요를 느껴, 2026년 3월 이후 Proxmox VE 기반 가상화 환경으로 이전했다. 플레이어 통신은 중계 서버 경유＋Tailscale VPN, 운영진용 웹 서비스는 Cloudflare Tunnel 경유, 관리 조작은 Tailscale 경유로 경로마다 보호 방식을 분리했다. 모니터링 체계(Prometheus/Grafana, 7종의 알림)도 구축하고, 팀 전체가 관리할 수 있도록 Crafty Controller 등 GUI 도구도 도입했다.

  • 참여자 약 30명 규모의 커뮤니티를 2022년부터 계속 운영
  • 물리 서버 2대를 Proxmox 클러스터로 묶어 LXC·VM 7대 이상으로 용도별 분리
  • "밖에서는 아무도 보고 있지 않다"는 상황에서도 손을 놓지 않고 견고한 환경을 정비

기술

  • Proxmox VE
  • LXC·VM
  • Tailscale
  • Cloudflare Tunnel
  • Nginx Proxy Manager
  • Prometheus·Grafana
  • Crafty Controller

서버 규칙 기초·조문화

법률 조문 형식을 따르면서도 참여자가 읽기 쉬운 서버 규칙을 기초

역할
규칙 기초·조문화 담당
기간
2022.9 — 현재

전신 서버의 특징과 커뮤니티 분위기를 감안하여, 참여자가 원하는 것과 안정적인 운영의 양립을 염두에 두고 규칙을 기초했다. 법령의 조문 형식을 따르면서도 구어적인 표현을 함께 넣어 참여자가 읽기 쉽게 하는 데 신경 쓰고 있다. 특히 운영 권한의 행사 범위를 엄격하게 정하여, 운영진 자신(본인 포함)의 권한 남용에 제동을 거는 설계를 중시하고 있으며, 대학에서의 전공인 헌법학의 사고방식을 실무에 응용하고 있다.

  • 현행 조문 수 85조, 제정 이래 두 차례의 대개정을 실시
  • 참여자 약 30명·운영진 약 6명 규모의 커뮤니티를 규율
  • 운영 권한의 행사 범위를 엄격화하여, 본인을 포함한 권한 남용에 대한 제동 장치를 설계(헌법학의 관점을 응용)

OpsBot — 운영 업무 자동화 Discord 봇

서버 운영의 신고·투표·허가 신청·독촉 등의 사무 처리를 자동화하는 Discord 봇

역할
설계·구현(개인 개발)
기간
2026.9 — 현재

서버 안에서 일상적으로 발생하는 신고 접수·투표 실시·기명 허가·독촉 통지 등의 사무 처리를, 봇의 명령어와 폼으로 끝낼 수 있도록 개발했다. Cloudflare Workers(TypeScript)＋D1을 API·데이터 관리 계층으로 삼고, Proxmox 위에서 돌아가는 Python 폴러가 Discord의 메시지·리액션을 상시 감시하여 각 처리를 트리거하는 2계층 구성으로 구현했다. Cloudflare Workers 무료 플랜은 cron 작업이 5개까지라는 제약이 있어, 독촉 점검이나 대장 갱신 등 여러 배치 처리를 하나의 cron으로 묶어 실행하는 스케줄링을 짜서, 플랜 범위 안에서 기능을 성립시켰다. 승인·반려처럼 판단이 필요한 처리는 반드시 사람의 입력을 기점으로 삼고, LLM(Claude)은 신청 내용의 미비 검출이나 작업 배정 후보 제시 등 "사람 손으로는 놓치기 쉬운 검출"에만 활용하는 설계로 했다. 현재는 작업의 자동 검출·배정 기능을, 검출 결과를 로그에만 기록하고 실제 통지는 하지 않는 시험 운용(섀도 모드)으로 동작을 확인하고 있다.

  • 신고 접수·투표·허가·독촉 등 여러 사무 처리를 명령어화하여 자동화
  • Cloudflare Workers(TS)＋D1과 Proxmox 위의 Python 폴러에 의한 2계층 구성으로 구현
  • Workers 무료 플랜의 cron 5개 제약 아래에서 여러 배치를 하나로 모으는 스케줄링을 설계

기술

  • Cloudflare Workers(TypeScript)
  • D1
  • Python(Proxmox CT 위의 폴러)
  • Discord API
  • Claude Code CLI

REWIS(전세계 철도 정보 시스템)

계속 늘어나는 노선망에서 "어떻게 가야 할지 모르겠다"를 해소하는, 현실의 환승 안내를 방불케 하는 웹 앱

역할
설계·구현(개인 개발 / 데이터는 각 철도 회사＝참여자로부터 순차 제공)
기간
2025.10 — 현재

Minecraft 속 철도망이 커지면서 현실의 철도 회사 못지않은 노선도가 만들어지는 한편으로, "어느 노선을 타야 목적지에 닿는지 모르겠다"는 참여자가 늘어난 데서 제작을 시작했다. GitHub Pages라는 정적 사이트의 제약 속에서 로그인과 데이터 쓰기를 구현할 필요가 있어, 처음에는 리포지토리 안의 JSON으로 관리하던 데이터를 Cloudflare Workers를 외부 정본으로 삼는 방식으로 바꾸고, 각 철도 회사(참여자)가 사업자용 페이지에서 직접 데이터를 편집할 수 있는 구조를 구축했다. 기존의 환승 안내 서비스를 연구하면서, PWA 대응으로 앱 같은 조작감과 PC 표시의 양립을 목표로 삼았다.

  • 정적 사이트 위에서 Cloudflare Workers를 외부 정본으로 삼은 데이터 편집 기능을 구현
  • 현재 7개 노선 34개 역에 대응, 앞으로 약 50개 노선·약 200개 역 규모로 확대 예정
  • PWA 대응으로 앱 같은 조작감과 PC 표시를 양립
