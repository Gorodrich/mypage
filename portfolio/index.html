01

自己紹介

法律を学びながら、気づけばサーバーも運用している。興味を持ったことにはとりあえず手を出してみる性分です。

中央大学法学部法律学科の4年生として法律学を学びながら、Minecraftサーバーの運営メンバーとしてインフラ管理にも携わっています。

初めにサーバー管理に関わり始めたきっかけはふとしたことで、当時参加していたサーバーの運営が続けられなくなったタイミングで、たまたま資金面で余裕があった自分がなりゆきでVPSを借りて管理を引き継いだことでした。その後は古いノートPCでの自宅サーバー運用へと落ち着き、最初はDynmapすらない最小構成からのスタートでした。もともとサイバー攻撃の種類や手口には昔から興味があったのですが、参加者のために機能を一つずつ追加していく中で、その興味とサーバー管理という役割がよく噛み合っていることに気づいていきました。「みんなのためによりよいものを提供したい」という思いと、「公開範囲が広がるたびにセキュリティホールを一つずつ潰していく」というインフラセキュリティ特有のパズルのような面白さが噛み合い、強い好奇心とやりがいを感じるようになりました。今ではセキュリティを含めたインフラエンジニアリング全般が関心の中心にあります。

法律への関心も、元をたどればセキュリティへの興味から生まれています。もともとは工学部進学も考えていましたが、Winny事件を知ったことがきっかけで、ソフトウェア開発者を巡るあの事件がセキュリティエンジニアの立場にも通じるものだと感じました。攻撃を防ぐには攻撃手法そのものを深く理解する必要があり、攻撃と防御は表裏一体です。そうした技術者や研究者を法律面から支える人材の必要性を意識したことが、法学への興味の出発点でした。加えて、実際にサーバールールの条文化作業に携わる中で、意味の取り違えを防ぐための法令用語の工夫や、緻密でありながらどこか人間味のある条文解釈の議論に惹かれ、法学徒として本格的に法律を学ぶことを決めました。

大切にしているのは、興味を持ったことに対して妥協しないことです。法律に関心を持てば法学部で学び、サーバーインフラに関心を持てば実際にサーバーを立て、仮想化にも挑戦する。そうやって興味の赴くまま行動を重ねてきました。根底には「誰かのために」何かをしたいという思いが強くあり、参加者のためにサーバーを改善することも、セキュリティエンジニアを支える法律家という将来像も、この思いが原点になっています。

    関心を持った領域には、経験の有無に関わらず実際に踏み込んでみることを大切にしています。進路や技術選定の場面でも、この姿勢を軸に判断してきました。

スキル

クラウド / インフラ

  • Proxmox VE

    物理2台をクラスタ化し、SDN(VXLAN)で仮想ネットワークを構築、LXC・VM 7台超を運用

  • Linux (Debian)

    全コンテナ・VMの基盤OSとしてサービス構築・systemd管理を担当。私用のノートPCでもUbuntu系のOSを利用

    ACLタグで役割を分離し、管理者・監視・Minecraftサーバー間のアクセス経路を設計

    venv構成でのインストール・systemdサービス化・自動再起動設定まで含め、チーム全体が扱えるGUI管理環境を整備

開発

  • Python

    OpsBotのCT102側（ポーリング処理・外部API連携）を実装

    OpsBotのCloudflare Workers側バックエンドを実装

    REWISのUI設計・スタイリングを一から構築

法学

Minecraftサーバーインフラ構築・運用

2台の自宅サーバーをProxmoxクラスタ化し、Minecraftサーバーと周辺サービスをアクセス制御込みで構築・運用

役割
サーバー構築・インフラ管理担当
期間
2022.11 — 現在

最初はUbuntu機にサーバーソフトを入れただけの状態から始まり、参加者・運営チーム・自分（管理者）という3種類の利用者ごとに「どこまでアクセスを許すか」を整理する必要性を感じ、2026年3月以降Proxmox VEによる仮想化環境へ移行した。プレイヤー通信は中継サーバー経由＋Tailscale VPN、運営向けWebサービスはCloudflare Tunnel経由、管理操作はTailscale経由と経路ごとに保護方式を分離。監視体制（Prometheus/Grafana、7種のアラート）も構築し、チーム全体で管理できるようCrafty ControllerなどGUIツールも導入した。

  • 参加者約30人規模のコミュニティを2022年から継続運用
  • 物理2台をProxmoxクラスタ化しLXC・VM 7台超に用途別分離
  • 「外からは誰も見ていない」でも手を抜かず堅牢な環境を整備

使用技術

  • Proxmox VE
  • LXC・VM
  • Tailscale
  • Cloudflare Tunnel
  • Nginx Proxy Manager
  • Prometheus・Grafana
  • Crafty Controller

サーバールール起草・条文化

法律の条文形式に準拠しつつ、参加者にとって読みやすいサーバールールを起草

役割
ルール起草・条文化担当
期間
2022.9 — 現在

前身サーバーの特徴やコミュニティの雰囲気を踏まえ、参加者が求めるものと安定運営の両立を意識してルールを起草。法令の条文形式に準拠しながら、口語的な表現も取り入れて参加者に読みやすくすることを心がけている。特に運営権限の行使範囲を厳格に定め、運営自身（自分を含む）の権限濫用に歯止めをかける設計を重視しており、大学での専攻である憲法学の考え方を実務に応用している。

  • 現行条文数85条、制定以来2回の大改定を実施
  • 参加者約30人・運営約6人規模のコミュニティを規律
  • 運営権限の行使範囲を厳格化し、自身を含む権限濫用への歯止めを設計（憲法学の視点を応用）

OpsBot — 運営業務自動化Discord Bot

サーバー運営の届出・投票・許可申請・督促などの事務処理を自動化するDiscord Bot

役割
設計・実装（個人開発）
期間
2026.9 — 現在

サーバー内で日常的に発生する届出受付・投票実施・記名許可・催促通知などの事務処理を、Bot上のコマンドとフォームで完結できるように開発した。Cloudflare Workers（TypeScript）+ D1をAPI・データ管理層とし、Proxmox上で動くPythonのポーラーがDiscordのメッセージ・リアクションを常時監視して各処理をトリガーする2層構成で実装。Cloudflare Workers無料枠はcronジョブが5本までという制約があるため、督促チェックや台帳更新など複数のバッチ処理を1本のcronにまとめて実行するスケジューリングを組み、枠内で機能を成立させた。承認・却下といった判断が必要な処理は必ず人間の入力を起点とし、LLM（Claude）は申請内容の不備検出やタスク割当候補の提示など「人手では見落としがちな検出」にのみ利用する設計とした。現在はタスクの自動検出・割当機能を、検出結果をログにのみ記録し実際の通知は行わない試験運用（シャドーモード）で動作確認中。

  • 届出受付・投票・許可・督促など複数の事務処理をコマンド化して自動化
  • Cloudflare Workers（TS）+D1とProxmox上のPythonポーラーによる2層構成で実装
  • Workers無料枠のcron5本制約下で複数バッチを1本に集約するスケジューリングを設計

使用技術

  • Cloudflare Workers（TypeScript）
  • D1
  • Python（Proxmox CT上のポーラー）
  • Discord API
  • Claude Code CLI

REWIS（全世界鉄道情報システム）

増え続ける路線網で「どう行けばいいか分からない」を解消する、現実の乗換案内さながらのWebアプリ

役割
設計・実装（個人開発／データは各鉄道会社＝参加者から順次提供）
期間
2025.10 — 現在

Minecraft内の鉄道網が拡大し、現実の鉄道会社さながらの路線図が作られる一方で「どの路線に乗れば目的地に着くのか分からない」参加者が増えてきたことから制作を開始した。GitHub Pagesという静的サイトの制約の中でログインやデータ書き込みを実現する必要があり、当初はリポジトリ内のJSONで管理していたデータをCloudflare Workersを外部正本とする方式に切り替え、各鉄道会社（参加者）が事業者向けページから直接データを編集できる仕組みを構築した。既存の乗換案内サービスを研究しつつ、PWA対応でアプリのような操作感とPC表示の両立を目指した。

  • 静的サイト上でCloudflare Workersを外部正本としたデータ編集機能を実現
  • 現在7路線34駅に対応、今後約50路線・約200駅規模へ拡大予定
  • PWA対応でアプリのような操作感とPC表示を両立

使用技術

  • HTML
  • CSS
  • JavaScript（バニラ）
  • GitHub Pages
  • Cloudflare Workers（外部データ正本・編集API）
  • PWA
